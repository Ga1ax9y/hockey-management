# Система управления хоккейным клубом

## 1. Назначение программного средства

«Система управления хоккейным клубом» (далее — Система) представляет собой
веб-приложение, предназначенное для комплексного управления деятельностью
хоккейной организации. Система обеспечивает автоматизацию учёта команд,
игроков, персонала, тренировочного процесса, соревнований, медицинских и
физических показателей, а также предоставляет средства аналитики
подготовленности спортсменов.

Программное средство реализовано по клиент-серверной архитектуре и состоит из
двух автономных компонентов:

- **бэкенд (backend)** — REST API, реализующий бизнес-логику и взаимодействие с базой данных;
- **фронтенд (frontend)** — одностраничное веб-приложение, обеспечивающее пользовательский интерфейс.

## 2. Функциональные возможности

Система обеспечивает выполнение следующих основных функций:

- **Аутентификация и авторизация** — регистрация и вход пользователей на основе
  JWT-токенов с разграничением прав доступа по ролям (Администратор, Менеджер,
  Тренер, Врач).
- **Управление пользователями** — ведение реестра сотрудников организации,
  назначение ролей, управление профилями и аватарами.
- **Управление командами** — создание и редактирование команд, привязка к
  сезону и лиге, назначение персонала.
- **Учёт игроков** — формирование карточек игроков, ведение антропометрических
  данных, фото, параметров контракта и привязка к команде.
- **Тренировочный процесс** — планирование тренировок с привязкой к команде и
  тренеру, оценка работы игроков.
- **Соревновательная деятельность** — учёт матчей, ведение протоколов и
  статистики игроков (голы, передачи, штрафные минуты, полезность и др.).
- **Медицинский блок** — регистрация травм и заболеваний, сроков восстановления.
- **Физическая подготовка** — фиксация физиометрических показателей игроков.
- **Карьера игроков** — история переходов между командами.
- **Аналитика подготовленности** — расчёт индекса готовности игроков и команд,
  построение диаграмм и отчётов.
- **Аудит действий** — журналирование ключевых операций пользователей.

## 4. Структура проекта

```
hockey-management/
├── backend/                 # Серверная часть (REST API)
│   ├── prisma/              # Схема БД и миграции
│   ├── src/

│   │   ├── middlewares/     # Промежуточные обработчики
│   │   ├── routes/          # Маршрутизация API
│   │   ├── seeds/           # Начальное наполнение данных

│   │   ├── lib/             # Клиент базы данных
│   │   ├── helpers/         # Вспомогательные функции
│   │   ├── types/           # Типы данных
│   │   └── generated/       # Сгенерированный Prisma Client
│   └── .env.example         # Пример файла конфигурации
└── frontend/                # Клиентская часть (React SPA)
    └── src/
        ├── components/      # Компоненты интерфейса
        ├── pages/           # Страницы приложения
        ├── services/        # Взаимодействие с API
        ├── hooks/           # Пользовательские хуки
        └── utils/           # Утилиты
```

## 5. Требования к окружению

Для развёртывания Системы необходимы следующие компоненты:

- **Node.js** версии 18 или выше (рекомендуется 20+);
- **npm** (входит в состав Node.js);
- **PostgreSQL** версии 14 или выше;
- учётная запись в **Cloudinary** (для хранения загружаемых изображений).

## 6. Развёртывание и запуск

### 6.1. Клонирование репозитория

```bash
git clone <адрес_репозитория>
cd hockey-management
```

### 6.2. Развёртывание бэкенда

1. Перейти в каталог бэкенда и установить зависимости:

   ```bash
   cd backend
   npm install
   ```

2. Создать файл конфигурации окружения:

   ```bash
   cp .env.example .env
   ```

3. Заполнить переменные окружения в файле `.env`:

   | Переменная           | Назначение                                      |
   |----------------------|-------------------------------------------------|
   | `DATABASE_URL`       | Строка подключения к PostgreSQL                 |
   | `DATABASE_PORT`      | Порт, на котором будет работать API (по умолч. 4000) |
   | `JWT_SECRET`         | Секретный ключ для подписи JWT-токенов          |
   | `LOG_LEVEL`          | Уровень детализации журналирования              |
   | `NODE_ENV`           | Режим окружения (`dev`, `production`)           |
   | `CLOUDINARY_NAME`    | Имя облака Cloudinary                           |
   | `CLOUDINARY_KEY`     | Ключ API Cloudinary                             |
   | `CLOUDINARY_SECRET`  | Секрет API Cloudinary                           |

4. Применить миграции базы данных:

   ```bash
   npx prisma migrate deploy
   ```

5. Выполнить наполнение справочных данных (роли):

   ```bash
   npx tsx src/seeds/roleSeed.ts
   ```

   При необходимости можно наполнить базу тестовыми данными игроков:

   ```bash
   npx tsx src/seeds/playerSeed.ts
   ```

6. Запустить сервер в режиме разработки:

   ```bash
   npm run dev
   ```

   После успешного запуска API будет доступен по адресу
   `http://localhost:4000/api/v1`.

### 6.3. Развёртывание фронтенда

1. Перейти в каталог фронтенда и установить зависимости:

   ```bash
   cd ../frontend
   npm install
   ```

2. Запустить приложение в режиме разработки:

   ```bash
   npm run dev
   ```

   Приложение будет доступно по адресу, отображаемому в консоли (по умолчанию
   `http://localhost:5173`).

> **Примечание.** Для корректного взаимодействия клиента с API базовый URL
> бэкенда (`baseURL`) в файле `frontend/src/services/api.js` должен соответствовать
> фактическому адресу размещения серверной части.

### 6.4. Сборка для эксплуатации (production)

#### Бэкенд

```bash
cd backend
npm run build
npm start
```

Команда `build` компилирует TypeScript-код в каталог `dist/`, после чего команда
`start` запускает собранный сервер.

#### Фронтенд

```bash
cd frontend
npm run build
npm run preview
```

Команда `build` формирует оптимизированный пакет статических файлов в каталоге
`dist/`, который может быть размещён на любом веб-сервере (Nginx, Apache и т. п.).
Команда `preview` предназначена для локальной проверки собранной версии.

## 7. API-интерфейс

Все маршруты API объединяются под префиксом `/api/v1`. Основные группы
эндпоинтов:

| Группа маршрутов    | Назначение                                     |
|---------------------|------------------------------------------------|
| `/auth`             | Регистрация, вход, получение текущего пользователя |
| `/users`            | Управление пользователями                      |
| `/roles`            | Управление ролями                              |
| `/players`          | Учёт игроков                                   |
| `/teams`            | Управление командами                           |
| `/trainings`        | Планирование тренировок                        |
| `/matches`          | Учёт матчей                                    |
| `/medicals`         | Медицинская информация                         |
| `/physicals`        | Физические показатели                          |
| `/match-stats`      | Статистика игроков в матчах                    |
| `/training-stats`   | Оценка работы игроков на тренировках           |
| `/schedule`         | Расписание команды                             |
| `/transfers`        | История переходов игроков                      |
| `/analytics`        | Аналитика подготовленности                     |
| `/logs`             | Журнал аудита действий                         |

## 8. Первоначальный вход

Для первого входа в Систему необходимо зарегистрировать пользователя с ролью
«Администратор» через интерфейс регистрации либо посредством соответствующего
API-запроса. Роль присваивается при создании пользователя. Дальнейшее управление
учётными записями и распределение ролей выполняется администратором.
